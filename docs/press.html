Antiloop — press & technical brief

An anti-loop watchdog for local autonomous agents. Everything on this page is measured, with the numbers and the limits stated the same way.

One line: Antiloop detects when a local LLM agent starts repeating itself — failed tool calls or a word/sentence loop — and breaks the cycle without killing the session.

Links: source · release 1.0.0 · integration manual · project page

Why it exists

Autonomous agents fail in two characteristic ways, and they need different answers:

  • Tool loops — the same failing command, the same unchanged re-read, the same edit, over and over. Tokens burn, nothing progresses, and killing the session throws away the work.
  • Text loops — a quantised model under greedy decoding starts repeating one word or one sentence and keeps going until the budget ends.

How it is built

LayerMechanismEffect
Watchdog servicestdlib-only Python service on loopback, token-protected detects repeated text, repeated tool calls, stagnation; per-session modes observe → warn → automatic; cannot stop a process
Agent-loop integrationHermes shell hooks (pre_llm_call, pre_tool_call)injects a recovery protocol; refuses only the repeated tool call and lets a different one through
Text-loop detectorin-process plugin, on_stream_delta detects a phrase/sentence loop roughly a second into generation, keyed per session+turn
Output protectiontransform_llm_output truncates a looped answer before it enters the transcript, keeping the meaningful prefix

Loop detection runs no LLM and no GPU work of its own.

What it explicitly does not do

  • No mid-generation cancellation. Hooks can refuse a tool call; they cannot cancel a model request already in flight. The docs say so everywhere it is relevant.
  • No cloud service, no telemetry, no external API, no LLM in the detection path.
  • It cannot stop, restart or signal any process — by design.

For a video or article

Three reproducible demonstrations exist, all offline:

  1. The loop and the fix. A pathological prompt against a local server, greedy versus repetition-penalty sampling — the token budget difference is visible on screen.
  2. The agent that refuses to repeat itself. An agent told to run the same failing command five times; the fourth and fifth are blocked with a recovery instruction.
  3. The transcript that stays clean. A looping answer, truncated before it is persisted, with the marker visible in the stored response.

Test logs, harness output and the integration manual are in the repository; a demonstration environment can be arranged.
